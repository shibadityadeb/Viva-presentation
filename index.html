Failure is scoped to a chunk

Invalid JSON retries once with the validation errors fed back to the model. A second failure marks that chunk failed and the document keeps going — one bad paragraph never loses a file.

Resolution happens before the write

Normalized title, then the alias table, then Dice-bigram similarity at 0.85. A hit updates the entity that already exists rather than creating a near-duplicate.

The provider is a parameter

One LLMProvider interface with five implementations — Anthropic, OpenAI, Gemini, local, and a rule-based mock that keeps the suite offline and deterministic.

Project one · packages/retrieval

What the Brain reaches for first

Every answer is assembled from ranked sources. The base weight per source kind is declared in one table, and position inside a kind decays it by 0.05 per rank — so ordering is a property of the code, not of a prompt, and it can be argued with.

Two deliberate calls sit in this chart. Web search is last, so internal company knowledge wins every tie by construction. The Brain’s own executed actions rank above meetings, because “what have I already done about this” is usually the freshest thing it knows.

Authorization as data reach

A source declares which scopes it serves and reads only what that scope allows. There is no imperative permission check to forget — a source that should not see something cannot query it.

ScopeReaches
TeamThe collective org brain: graph, memory, meetings, and every member’s synced Drive, Docs, Calendar and Gmail
PersonalAll of the above, plus your own executed actions — which never surface in a team chat

Adding a source is one file

Implement RetrievalSource, add it to the default list, declare its scopes. Slack, GitHub or a CRM would change nothing else in the stack.

Project two · UNBIFY Discover

The Discover journey

PART ONE — MEANING

Discover

Four chapters and a Final Mirror. Evidence decides which closing beats exist — what survived, what we changed our mind about, what we still would not claim. No personality slots, no prescribed career.

PART TWO — VALUE

Materialization

The story becomes objects you can test: a professional position, capability and leverage maps, gaps, ranked directions — and for each direction, the cheapest experiment that would settle its real uncertainty.

PART THREE — WORK

My UNBIFY

A workspace that persists: questions that sharpen precision, actions ranked by progress. Dismissing something is ranking feedback, and an experiment’s outcome is the strongest evidence the system receives.

Object lifecycle — every materialized object moves through this
new→ exploring→ saved→ testing→ active→ completed /dismissed
The hard rule

The workspace, and the Opportunity Map inside it, are unreachable before Chapter 4 closes — enforced by a server-owned state machine, not by the client, and covered by tests.

Project two · knowledge, interpretation, thresholds

The intelligence core

L1

Explicit facts

What the user actually said, stored with its provenance

L2

Derived facts

Conservative normalizations, and nothing more adventurous

L3

Hypotheses

Carry supporting and contradicting evidence ids, versioned — never silently overwritten

L4

Actionable conclusions — withheld

Role-level analysis is blocked at the validation layer until several independent sources agree.

Professional facts 2 / 4
Supported features 1 / 2

A supported feature is a dimension at confidence ≥ 0.60 (PROFESSIONAL_SURFACE) carrying at least 2 pieces of evidence (HYPOTHESIS_MIN_EVIDENCE). Both gate thresholds live in one versioned file, thresh_v1, so tuning stays auditable.

Abstain beats overreach

A reveal softens or stays silent when the claim would outrun the evidence. Silence is a valid outcome.

Corrections cascade

Being told we were wrong writes inference_feedback and invalidates every conclusion downstream of it.

Ambiguity is named, not resolved

“I manage codes and softwares” becomes works_with_software plus an open ambiguity — never a management inference.

A refusal has to say what is missing

The gate returns counts, not a boolean, so an abstention screen can name the gap. “Not enough evidence” is a verdict about the system — a person cannot recognise themselves in it.

Latency is measured, not guessed

Every request records how long each phase actually took, against a budget declared in code. Anything over budget is flagged on the row itself, so a complaint about feel is traceable to a phase instead of argued about.

Narrative generation has its own 6-second budget and sits outside this total — the journey completes with the model offline, so it can never be on the critical path.

The finding that mattered most was not in the code at all. One interaction is roughly 20 database round trips, so the database’s distance dominates everything else I could tune.

Same code, same query count, an order of magnitude apart. Put the database next to the users — measured, then written into the deployment notes so nobody rediscovers it.

Before any of this, the client acknowledges the tap locally in about 3 ms — the choice settles, the rest softens, duplicate input locks — and the leave animation starts alongside the request rather than after it. Submission is idempotent, so a retry cannot double-count evidence or advance a chapter twice.

Project two · the opportunity layer

World intelligence, on one database

01

Ontology

Occupations, aliases and external mappings — trades, clinical, legal, military, retail and knowledge work, not a hardcoded career list

02

Ingestion

Every source carries a compliance record. One community post is never market evidence.

03

Signals

Aggregated with confidence, source diversity and recency decay — conflicts between sources are kept, not averaged away

04

Matching

Your evidence projected into capability space; regulated work gated on eligibility; thin coverage abstains and queues a targeted refresh

No Redis. No Celery. No broker.
  • intelligence_jobs is the queue, claimed with SELECT … FOR UPDATE SKIP LOCKED.
  • A scope hash collapses identical concurrent requests: twenty people asking the same question cause one scrape — asserted by a test.
  • A per-scope cooldown stops refresh loops when a signal simply is not obtainable. The system says so instead of scraping forever.
  • Freshness is checked per signal — job postings age in a day, occupation definitions in months.

Refresh returns a state, never a stale answer pretending to be fresh: CURRENT · REFRESHING · PARTIAL · STALE_BUT_USABLE · INSUFFICIENT
